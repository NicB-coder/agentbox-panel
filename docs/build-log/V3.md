# agentbox panel — v3: simpler, fully in the panel, deep research

Read `CLAUDE.md`, `WORKFLOWS.md`, `HELPER.md` and `NOTES.md` first. Same design language (font, colors, squircles,
pills), plain words, beginner first. This is the version Nic uses every day from now on.

## You are working unattended

Nic is asleep and busy with school. Don't ask questions. Decide, write it in `NOTES.md` under "v3 — Decisions I made",
keep going. Branch `build/v3` from `main`, commit after each milestone, push, test every milestone with Playwright at
1366px and 390px on a separate dev copy (own database copy, port 3100, schedules off). At the end, open ONE pull request.
If usage runs out, stop cleanly; you'll be resumed after the reset. **Finished and polished beats more features.**
Never leave a half-built feature visible; hide it and note it.

## 0. Leftovers first

If the Helper review fixes aren't on `main` yet (Create-it twice, prompt injection with fixed labels for risky actions,
pruning busy chats, tools endpoint secret, unit tests for finalize/actionFor/chipFor, small fixes), do them first.

## 1. One agent per job (replaces premade agents)

- Remove Builder, Reviewer, Site Checker and Overnight from the grid (archive them, don't delete history). Keep Heartbeat.
- **New task** creates a **new agent** named after the job ("Arcade site", "Helper fixes") with the task as its prompt.
- Clicking an agent shows its job and lets Nic **add a follow-up** that continues the same job: same project, same
  branch and pull request if one is open, with what it did before as context. Nobody edits an agent to repurpose it.
- Finished agents can be **archived** (an "Archived" filter shows them).

## 2. One "Start a task" panel, used everywhere

New task button, agent follow-ups, Inbox ideas and the Helper all open the same panel:
- Big box: **What should it do?**
- **Project** (with "Add a project…").
- **When does it run?** Now · Every hour · Every day · Certain days. Day/time pickers show immediately when needed,
  plus "Next run: today at 6:00 PM". Never hidden.
- **Freedom:** Look only · Check with me first · On its own. One control replacing "What is it allowed to do?" and
  "How should it work with me?". "On its own" = auto, always delivered as a pull request. Drop the Suggest/Make split.
- **Careful / Quick** (default Careful, see 3).
- **More options** (folded): time limit, model (Fast / Smartest), connectors, Tell me when, Ask me each step.
- Short labels only. Every explanation lives in an ⓘ bubble. Apply this rule to every control in the app.

## 3. Careful mode (default for every task)

Build → review (different model, e.g. Opus reviews Sonnet) → fix, looping until the review passes (max 2 rounds) →
polish and optimize → final review → Inbox, ready to merge. Quick skips the extras for tiny tasks.
- Nic never schedules or requests a review. The Inbox shows "Reviewed ✓ · 2 fixes made · optimized" with just
  **Look at it** and **Merge it**. "Get a second opinion" lives under More.
- On any pull request not made this way, show review findings with a **Send back to fix** button (continues the same job).

## 4. Everything happens in the panel

- **Projects** is a real button in the top header: Agents · Workflows · Inbox · Projects.
- **See what changed** on every pull request: plain-English summary, before/after screenshots when it's a page or game,
  code changes behind a toggle. **Comment / Send back with a note** from the panel.
- **Preview / Play:** open a project's site or game live from the panel (serve the project's files or dev server on
  127.0.0.1 behind a panel route so it works over Tailscale). Show a Play button on shipped game/site items.
- **Update agentbox** button (Settings and Help): pulls `main`, installs, builds, and restarts the panel itself, with
  a clear progress view and a plain success/failure message. If the build fails, keep the old version running.
- **Machine** page: battery and charging, disk space, uptime, whether Tailscale is connected, heartbeat, which
  accounts are logged in, last restart.
- **Terminal** page: a real terminal into the agent account, for the rare times Nic still needs one.
- Nothing in the normal flow ever needs SSH or unlocking the keychain.

## 5. Show what's happening

- Home grid: running agents and anything that needs Nic go first, left to right, with a light tint of the agent's
  color (6–8%) and a gently pulsing dot. Idle and done agents after.
- Tiles never just say "Running": task in a few words, a live "right now" line, step 3 of 5 with a small bar, and time
  so far. Workflow tiles show which step and what it's doing.

## 6. Never lose work to usage limits

Agent runs (not only workflows) that hit the usage limit show **Waiting · back at 3:00 PM** and continue by themselves
in the same copy and conversation once usage is back (real reset time, 30-minute retry as fallback). Same for scheduled
agents and the Helper. Stop for good only at the run's own time limit or if Nic presses Stop.

**Time limits are different from usage limits.** A run that hits its own time limit stops (that's the safety cap),
but show it as "Ran out of time" with a **Keep going (+30 min)** button that continues the same job, not a red
failure. For scheduled runs, a newer run replaces older stopped ones: clear stale stopped items from the Inbox
automatically so they don't pile up (e.g. two old "Scheduled run · ran out of time" cards from the hourly Reviewer).
Set sensible default time limits per kind of work so routine runs rarely hit them.

## 7. Tell Nic when something ships

Every ship or merge creates an Inbox item ("Shipped: Arcade site", what changed, Play link, pull request) that stays
until opened, plus a Discord message if notifications are on. Find and fix why the arcade workflow's Tell me step was
silent. Inbox filter: "Done & shipped".

## 8. Workflows: clearer

A big **"What should this workflow make?"** box at the top of the editor (default task for Run now and Test run;
Run now shows it prefilled and editable). Each step's own instructions clearly labeled. Use the same Freedom and
Careful/Quick controls and short-label rule in steps.

## 9. Connectors

A **Connectors** page plus a Connectors choice in the task panel and workflow steps: Gmail, Google Calendar, Google
Drive, Slack, Notion, GitHub and others. Use Claude Code's MCP support (check `claude mcp --help` and current docs for
remote/OAuth servers). Each shows Connected / Not connected and, in plain words, what it lets agents do. Per task or
step, Nic ticks which ones it may use. Anything that sends, deletes or books is "Check with me first" by default.
Secrets stay in the Keychain. If a connector can't be set up without Nic (e.g. a sign-in), make the Connect button
walk him through it and note it under "v3 — Needs Nic".

## 10. Deep research

A **Research** kind of task (a choice at the top of the Start a task panel: Build something · Research something):
- Nic types a question. The agent plans sub-questions, searches widely, reads the actual sources, cross-checks claims
  between sources, and runs parallel subagents for big questions.
- Output is a **Report** page in the panel: a short answer first, then sections, then every source as a link, with
  claims tied to sources and anything uncertain flagged. Download as PDF or Markdown. Optionally saved to a project.
- Defaults: Look only, Smartest, 60-minute limit, Careful (a reviewer checks the report against its sources before it
  reaches the Inbox). Reports get their own Inbox items and a "Reports" filter.
- A **Research** step in workflows uses the same engine.

## 11. Helper

Much shorter replies, every step still included. Slower, calmer typing; no auto-scroll while it types (a small
"↓ New text" button instead). It knows all the v3 pages and can start the Start a task panel prefilled.

## 12. Big jobs: remove everything that stops long projects from running in the panel

Goal: a job like this whole v3 build (hours long, across usage resets, changing the panel itself) can be started from
the panel and finish without Terminal. Find and fix every blocker, including these:
- **Time caps:** a **Big job** option (in the task panel and as a workflow step setting) with no fixed wall-clock cap.
  Instead it works milestone by milestone with a usage budget, and Nic can raise the budget or stop it any time.
- **Usage resets:** waits and resumes automatically (section 6), no matter how many resets it spans.
- **Long briefs:** attach a brief file (upload a .md, or pick one from the project), stored with the job, instead of
  pasting pages into a text box.
- **Checkpoints:** big jobs commit and push after each milestone and keep a progress file, so any interruption resumes
  from the last finished milestone. Use a fresh session per milestone with a written handoff instead of one giant
  conversation that runs out of context.
- **Survive panel restarts and Mac restarts:** agent runs must not be child processes that die with the panel. Run them
  supervised (e.g. their own launchd jobs) so they keep going while the panel restarts or updates, and the panel
  reattaches to them. After a Mac restart, unfinished jobs resume once the agent account logs in ("Resumed after restart").
- **Jobs that change the panel itself:** build and test on the dev copy (port 3100). At the end, **Install it** runs
  the Update flow with a health check, and **automatically rolls back** to the previous version if the new one doesn't
  come up. Offer "Install automatically when finished" for these jobs.
- **Sign-in expiry:** detect when Claude Code or GitHub needs signing in again and show a clear "Sign in again" button
  instead of failing quietly.
- **Sharing usage:** while a big job runs, optionally hold small scheduled runs so they don't eat its usage. Show the
  queue.
- **Disk space:** clean up old copies (worktrees) automatically after a few days, show disk space on the Machine page,
  and warn before it runs low.
- **Progress:** the job page shows the milestone checklist, current milestone, time so far, usage used, and a Discord
  ping per finished milestone.
Test it end to end with a small multi-milestone job on the dev copy, including a forced usage-limit wait (simulate it),
a panel restart mid-job, and an install with a deliberately broken build to prove the rollback.
